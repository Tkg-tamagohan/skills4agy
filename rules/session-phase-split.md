# 開発フェーズの区切りや長期化では別セッションへの移行を誘導する

一つのセッションを長く続けすぎない。
セッションが長くなるほどコンテキストが膨らみ、前半の指示や決定事項が後半の作業へ正しく反映されにくくなる。
開発フェーズの区切りが見えたら現セッションの成果物を確定し、次のフェーズは新しいセッションで行うようユーザーに誘導する。

## 手順

1. 現フェーズの成果物(要件定義書、決定記録、実装計画、PR など)を確定させ、このセッションの作業を完了させる。
2. 別セッション(`/boost`、`/swarm`、新規会話など)での実行を前提に計画書やプロンプトを作成した場合、計画 Artifact への本文なし承認(Approve/Proceed)だけでは現セッションでコード変更に着工しない。
   現セッションで実装してよいか、未決事項の回答とあわせてユーザーへ確認する。
3. フェーズの切り替わりを検出したら、参照すべき文書や PR、引き継ぐ決定事項、そのまま使える再開プロンプトを添えて別セッション移行を提案する。
   引き継ぎメモと再開プロンプトの具体的な作成手順はスキル `session-handoff` に従う。
   引き継ぎが PR のマージ後をまたぐ場合(head ブランチ自動削除有効時を含む)は、マージ後の基準点(`main` やタグ)と新規ブランチ手順を明記する。
4. 複数セッションで同一リポジトリを分別実行するとき、後続セッションは未コミット差分やシンボル出現だけで先行セッション完了とみなさず、先行コミットまたはユーザーの完了連絡を起点にする。
   未確定の間は非依存タスクのみ先行するかユーザーへ確認する。
5. フェーズの切り替わりがなくても作業が長期化した場合は、コミットや PR 作成など区切りのよいところで同様に移行を提案し、続行指示時は必要に応じて `/compact` を案内する。

## 対象外

- 長期化していない同一フェーズ内の継続作業(実装中の修正、レビュー対応、CI 失敗への対処など)
- フェーズの切り替わりが想定されない小規模なタスク
