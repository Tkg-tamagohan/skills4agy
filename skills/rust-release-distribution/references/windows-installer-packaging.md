# Windows 向けパッケージングとインストーラ実装の罠

Windows 向けアプリケーションのインストーラ生成、配布スクリプトのテスト、アクセス制御、および導入失敗時の復旧で踏む環境依存の罠と対策をまとめる。
`run_command` やローカル CLI 実行における基本のシェル罠、PowerShell 5.1/7 混在環境での `PSModulePath` 除去と `Microsoft.PowerShell.Security.psd1` 明示読込、および `MethodInvocationException.InnerException` 連鎖展開の基本手順は `windows-cli-pitfalls` を参照する。

## インストーラ生成と PowerShell 連携の境界

- NSIS（`makensis`）などのインストーラ生成では、バージョン番号や入力ディレクトリをマクロ引数で明示注入し、出力インストーラは作業ツリー外の一時ディレクトリ（ランナー一時領域等）へ出力してから配布物ディレクトリへ集約する。
- インストーラから 64 ビット Windows PowerShell 5.1 を起動して ACL 設定やファイル置換を実行するときは、親プロセスが PowerShell 7 系であっても `Get-Acl` や `Set-Acl` とファイルロック再試行が破綻しないよう、`windows-cli-pitfalls` が定める `PSModulePath` の PS 6/7 パス除去、セキュリティモジュール明示読込、および `.InnerException` 連鎖展開をインストーラ用スクリプト冒頭とリトライ補助関数へ必ず組み込む。

## SDDL と SID による ACL 保護

インストール先や共有データディレクトリのアクセス制御では、ローカルユーザー名や日本語などロケール依存の表示名に頼ってはならない。
Entra ID（Azure AD）参加端末や Active Directory ドメイン環境ではアカウント名の解決形式が変わり得るため、SDDL（Security Descriptor Definition Language）文字列の SID で対象を識別して設定および検証を行う。

```powershell
# 例示：SDDL 文字列でローカル管理者、SYSTEM、Entra ID、ドメイン SID を許可判定する
$sddl = (Get-Acl -LiteralPath $targetDir).Sddl
$hasExpectedSid = $sddl -match '(SY|BA|S-1-12-1-\d+(?:-\d+)+|S-1-5-21-\d+(?:-\d+)+)'
if (-not $hasExpectedSid) {
  throw "Unexpected ACL SDDL: $sddl"
}
```

## インストールとアップグレード失敗時のロールバック保全

導入やアップグレードの途中でサービス起動やファイル配置が失敗した場合は、中途半端な残骸を残さず安全側へ巻き戻す構成を採る。

1. サービス停止処理には待機上限（例として 15 秒）を必ず設け、停止完了まで無限待機してインストーラがハングするのを防ぐ。
2. 新規インストールが途中で失敗したときは、直前に登録したサービスやホスト連携（プロトコルハンドラ、ブラウザ連携設定等）の解除を試行する。
3. アップグレードが途中で失敗したときは、置換前に退避しておいた既存バイナリと配布設定ファイルを元の場所へ復元し、更新前にサービスが起動していた場合のみサービスを再起動する。
4. アンインストール処理は既定で設定履歴、データベース、およびログを保全し、明示的な完全消去オプション（例として `/PURGE_DATA` や `-PurgeData`）が指定された場合のみ共有データディレクトリを削除する。
   完全消去時は先にログファイルのハンドルを閉じてからディレクトリ削除を実行し、マシン単位のアンインストール対象外となる各ユーザープロファイル配下との境界をランブックの保全一覧表で明示する。

## Windows ランナーでの配布検証スクリプト試験

パッケージ組み立てや署名検証を行う補助スクリプトの単体テストを Linux ランナーだけで実行すると、パス区切り文字の違い、既定ロケール（cp932 等）での UTF-8 読み書き失敗、および閉じ忘れたファイルハンドルによる一時ファイル削除失敗を見逃す。
配布スクリプトの構文検査と単体テストは `github-actions-ci` に従い、`windows-latest` ランナー上でも厳格警告モード（例として Python の `python -W error -m unittest`）で実行し、`ResourceWarning` やエンコーディング不整合を CI 段階で早期検出する。

## 原則

- インストーラ生成物は一時領域へステージングし、呼び出す PowerShell 5.1 スクリプトには `windows-cli-pitfalls` のモジュール分離と例外展開を組み込む。
- ACL の設定と検証には表示名ではなく SDDL の SID 正規表現を用い、Entra ID やドメイン端末の差異を吸収する。
- 導入失敗時のロールバックと既定アンインストールのデータ保全範囲を分け、共有ログのハンドル解放とユーザー別領域の対象外境界を明記する。
- 配布スクリプトの単体テストは `windows-latest` 上で厳格警告付きにより実行する。
