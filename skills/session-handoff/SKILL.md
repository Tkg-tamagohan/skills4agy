# セッション引き継ぎメモの作成手順

現在のセッションを軽量に区切り、新しいセッションへ最小限のコンテキストで作業を引き継ぐためのメモと再開プロンプトを作成する。
ゴールは、次セッションが不要な再調査をせずに「最初の一手」から再開できる状態を、短い出力で用意することである。

## 責任範囲の境界

- **移行タイミングの判断**：開発フェーズの切り替わりや作業長期化を検知して別セッション移行を提案する判断は、ルール `session-phase-split` に委ねる。
  - 本スキルは、移行を決めたあとに引き継ぎメモと再開プロンプトを組み立てる手順だけを扱う。
- **同一セッション内のコンテキスト圧縮**：同一セッションを継続したまま履歴を圧縮する操作は組み込みコマンド `/compact` の役割であり、本スキルの対象外とする。
- **過去セッション横断の効果測定**：蓄積された `transcript.jsonl` 群のトークン消費、キャッシュヒット率、ルール遵守の定量監査は `session-context-audit` に委ねる。
- **Decisions API の一般仕様と質問設計**：`gemini-decision-1` のエンドポイントや質問型の仕様は、スキル `gemini-decisions-api` に委ねる。

## 手順

1. 軽量な現状確認と長大履歴の事前選別を行う。
   - `git status -s` と `git diff --stat` を実行し、直近の会話で確定した事項を確認する。
   - この段階で新たな大規模ファイル探索、長時間のビルド、重いテスト実行は行わない。
   - 次の省略条件に該当する場合を除き、同梱の Decision 1 事前選別 CLI を 1 回実行して `transcript.jsonl` から重要ステップを抽出する。
     - 直前に要件定義書、計画書、決定記録 Artifact 等へ確定仕様、対象ファイル、次の一手のすべてを総括済みであり、その後に新たな調査や試行錯誤が発生していない場合。
     - 開始から数ターン以内の明白な短会話で、過去の決定事項や失敗パターンの取りこぼし余地がない場合（判断に迷う場合は CLI 側のしきい値判定へ委ねる）。
     - ユーザーが手動要約のみを指定した場合。
   - 通常時は `--min-steps 80 --min-bytes 150000` を付けて実行し、80 ステップ以上または 150 KB 以上の会話を選別対象にする（両方未満の短会話では API を呼ばず 0 コストで自動スキップされるため、そのまま手動確認のみで次手順へ進む）。
   - コンテキスト圧縮（`/compact` や自動圧縮）の発生後はステップ数やサイズにかかわらず前半の決定事項が欠落しているため、`--min-steps` と `--min-bytes` を外して強制実行する。
   - `--conversation-id` には `<user_information>` の `Conversation ID` を指定し、並列セッションやサブエージェント稼働時に別会話を誤認するおそれがある `--latest` は使用しない。
   - 作業ディレクトリに依存しないよう `"$HOME/.gemini/config/plugins/shared-skills/..."` 形式で呼び出すか、`Available skills` に提示される本スキルの絶対パスから同階層の `scripts/triage_transcript_decision1.py` を解決する。
   - `App Data Directory` が既定の `~/.gemini/antigravity` と異なる環境では `--app-data-dir <path>` を併用する。
     ```powershell
     $env:PYTHONUTF8="1"; $env:PYTHONIOENCODING="utf-8"
     # 通常実行（80 ステップ以上または 150 KB 以上なら選別し、両方未満なら API 非呼び出しでスキップ）
     python "$HOME/.gemini/config/plugins/shared-skills/skills/session-handoff/scripts/triage_transcript_decision1.py" --conversation-id <conversation-id> --min-steps 80 --min-bytes 150000
     # コンテキスト圧縮発生後の強制実行（しきい値なし）
     python "$HOME/.gemini/config/plugins/shared-skills/skills/session-handoff/scripts/triage_transcript_decision1.py" --conversation-id <conversation-id>
     ```
   - CLI はシークレットをマスクした上で 1 回の Decision 1 呼び出し（出力トークン 0）により各ステップを `keep_decision`、`keep_gotcha`、`keep_state`、`drop_noise` へ分類し、末尾の直近ステップを無条件保護して Markdown で出力する。
   - `GEMINI_API_KEY` 未設定、通信エラー、安全フィルタ遮断（終了コード `3`）、またはしきい値未満スキップのときは、そのまま従来の手動確認へフォールバックする。
   - API キー不要で前処理結果とペイロードを点検するときは `--dry-run` を付ける。
2. 次の圧縮ルールに従って引き継ぎメモを作成する。
   - 出力全体は 1,500〜2,500 トークン程度を目安に簡潔にまとめる。
   - ファイル全文や長い生ログは貼らず、コード位置は `path/to/file.ext:L10-L45` 形式で記載する。
   - テストやビルドの失敗ログは、原因を示す核心の 3〜5 行だけを抜粋する。
   - 解決済みの試行錯誤の経緯は省き、「確定した結論」と「踏んではいけない失敗パターン」だけを残す。
   - ユーザーから追加の指示や引数がある場合は、それを最優先で `Next Step` に反映する。
3. 引き継ぎメモと再開プロンプトを出力する。
   - 既定ではチャット本文に直接出力し、末尾に次セッションへそのまま貼り付けられる起動プロンプトを添える。
   - 作業対象リポジトリを未追跡ファイルで汚さないため、ユーザーの指定がない限りリポジトリ内へファイルを新規作成しない。
   - ユーザーが保存先パスを指定した場合だけ、そのパスへ書き出して起動プロンプト内の参照パスを合わせる。

## 引き継ぎメモのテンプレート

```markdown
# Handoff: <タスク名>

## 1. Goal & Current Status
- 目的: <1〜2行で完了条件を明記>
- 現在地: <完了したこと / 未完了のこと>

## 2. Decisions Locked（確定済みの設計・仕様）
- <確定した仕様・制約・採用した方針を箇条書き>

## 3. Modified / Target Files
- `path/to/file_a.ts:L12-L58` — [済] <変更内容の要約>
- `path/to/file_b.ts:L100-L140` — [次] <これから行う修正の意図>

## 4. Failed Attempts & Gotchas（再発防止）
- <試してダメだったアプローチや環境固有の制約>

## 5. Next Step
- 最初の一手: <次セッション開始直後に実行すべき具体的アクション 1〜3 件>
- 基準点・前提: <参照すべきブランチ・コミット・未マージ PR などがあれば記載>
```

## 次セッション開始用の起動プロンプト

チャット出力をそのまま貼り付ける場合（既定）は次の形式を使う。

```text
以下の引き継ぎメモを読み込み、Section 5 の「最初の一手」から作業を再開してください。
対象外のファイル読み込みや不要な再調査は行わず、指定されたファイル範囲に絞って進めてください。

<ここに引き継ぎメモを貼り付け>
```

ユーザーが指定したパス（例: `<保存先パス>`）へ書き出した場合は次の形式を使う。

```text
`<保存先パス>` を読み込み、Section 5 の「最初の一手」から作業を再開してください。
対象外のファイル読み込みや不要な再調査は行わず、指定されたファイル範囲に絞って進めてください。
```

## ユーザー側の呼び出し目安（2026-11 実測ベース）

エージェントは進行中セッション自身のトークン使用量や経過時間をツールから直接観測できないため、以下はユーザーが本スキルを呼び出す目安として扱う。

- コンテキストが 250K〜350K トークンに近づいた時点（約 500K 付近の自動圧縮を待たず、文脈希釈とターン単価増を抑える目的）。
- 設計案や出力を数分以上かけて人間がレビューまたは検討する直前。
- 30 秒以上かかる重いビルドや E2E テストを実行する直前（重い処理はエージェント外で手動実行し、失敗時のみ原因の数行を渡す）。
- 探索や計画のフェーズが完了し、実装フェーズへ移行する時点（長大セッション内で計画と実行を往復させない）。

モデル別のキャッシュヒット率やピーク消費の確認は `session-context-audit`（`--scope parent`）の実測結果を参照する。

## 原則

- 引き継ぎメモの作成自体でコンテキストや時間を浪費しないため、大規模なコード再探索や重いテストは避け、長大履歴の振り返りは出力トークン 0 の同梱 CLI に委ねる。
- 未指定で作業リポジトリ内に一時ファイルを残さない。
- 実測に依存する数値目安は恒久手順と分離し、`session-context-audit` の計測結果で見直せる形を保つ。
